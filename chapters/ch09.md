# Chapter 9 — Testing Terraform Code

## Core Idea
Testing infrastructure is unique because validation requires interacting with real cloud provider APIs, creating actual infrastructure assets, and incurring costs. A complete testing strategy combines fast static analysis (`tflint`, `tfsec`), native HCL unit testing (`terraform test` with mock providers), and end-to-end integration testing using Go (`Terratest`).

---

## Frameworks Introduced

### 1. The Infrastructure Testing Pyramid Framework

```
               / \
              /   \         End-to-End Tests (Full System, Slowest, $$$)
             /     \
            /-------\       Integration Tests (Terratest: Deploy & HTTP Assert)
           /         \
          /-----------\     Native Unit Tests (terraform test / Mocks, Fast, Free)
         /-------------\    Static Analysis (tflint, checkov, fmt, validate, Instant)
```

| Layer | Tools | Execution Speed | Cost | Catches |
|---|---|---|---|---|
| **Static Analysis** | `terraform fmt`, `validate`, `tflint`, `checkov`, `tfsec` | Instant (Seconds) | Free ($0) | Syntax errors, invalid instance types, security misconfigurations |
| **Native Unit Tests** | `terraform test` (`.tftest.hcl`), Mock Providers (TF 1.7+) | Fast (Seconds/Mins) | Free ($0 with mocks) | HCL logic bugs, variable validation, conditional module outputs |
| **Integration Tests** | `Terratest` (Go), `test-kitchen` | Medium (5–15 mins) | Low ($) | Live cloud API deployment, ALB HTTP response, database connection |
| **End-to-End Tests** | `Terratest` multi-stage suites | Slow (15–45 mins) | Medium ($$) | Inter-service network routing, cross-account IAM, failover validation |

### 2. The Sandbox Environment Isolation Framework
- **Dedicated Test Accounts**: Never run integration tests against staging or production accounts. Use isolated AWS sub-accounts (`aws-sandbox`).
- **Automatic Teardown Guard (`defer`)**: In Go/Terratest code, always register `defer terraform.Destroy(t, opts)` *immediately* after setting up options.
- **Resource Namespacing**: Append unique random strings (`random_pet`, `random_uuid`) to resource names to avoid global naming collisions during parallel test runs.

## Code Examples

### 1. Layer 1: Static Analysis Shell Pipeline (`scripts/lint.sh`)
```bash
#!/usr/bin/env bash
set -e

echo "=== 1. Checking Formatting ==="
terraform fmt -check -recursive

echo "=== 2. Validating Syntax ==="
terraform init -backend=false
terraform validate

echo "=== 3. Running TFLint ==="
tflint --init
tflint

echo "=== 4. Security Scan with Checkov ==="
checkov -d . --framework terraform
```

### 2. Layer 2: Native HCL Unit Test with `terraform test` (`tests/web_cluster.tftest.hcl`)
```hcl
# Set up test variables
variables {
  server_port  = 8080
  cluster_name = "test-cluster"
  min_size     = 2
  max_size     = 4
}

# Unit Test 1: Validate variable assertions without applying
run "validate_input_bounds" {
  command = plan

  assert {
    condition     = aws_autoscaling_group.example.min_size == 2
    error_message = "ASG min_size did not match configured test input"
  }
}

# Unit Test 2: Execute plan & assert calculated outputs
run "verify_alb_naming_prefix" {
  command = plan

  assert {
    condition     = startswith(aws_lb.example.name, "web-alb")
    error_message = "ALB name must start with 'web-alb' prefix"
  }
}
```

### 3. Layer 2: Unit Testing with Mock Providers (TF 1.7+ `override_provider`)
```hcl
# Override AWS provider to simulate API responses without hitting real AWS
override_provider "aws" {
  mock_data "aws_ami" {
    defaults = {
      id   = "ami-0123456789abcdef0"
      name = "ubuntu/images/hvm-ssd/ubuntu-jammy-22.04-amd64-server-mock"
    }
  }
}

run "test_with_mocked_aws" {
  command = plan

  assert {
    condition     = aws_launch_template.example.image_id == "ami-0123456789abcdef0"
    error_message = "Launch template failed to consume mocked AMI ID"
  }
}
```

### 4. Layer 3: Integration Testing with Go (`test/web_cluster_test.go`)
```go
package test

import (
	"crypto/tls"
	"fmt"
	"strings"
	"testing"
	"time"

	"github.com/gruntwork-io/terratest/modules/http-helper"
	"github.com/gruntwork-io/terratest/modules/random"
	"github.com/gruntwork-io/terratest/modules/terraform"
)

func TestWebClusterIntegration(t *testing.T) {
	t.Parallel()

	// 1. Generate random resource prefix to avoid naming collisions
	uniqueID := strings.ToLower(random.UniqueId())
	clusterName := fmt.Sprintf("test-web-%s", uniqueID)

	// 2. Define Terraform Options
	opts := &terraform.Options{
		TerraformDir: "../examples/web-cluster",
		Vars: map[string]interface{}{
			"cluster_name": clusterName,
			"server_port":  8080,
		},
		// Retry intermittent cloud API errors automatically
		MaxRetries:         3,
		TimeBetweenRetries: 5 * time.Second,
		RetryableTerraformErrors: map[string]string{
			".*RequestLimitExceeded.*": "AWS API rate limit hit",
			".*TLS handshake timeout.*": "Network glitch",
		},
	}

	// 3. MANDATORY: Register Destroy cleanup on test exit
	defer terraform.Destroy(t, opts)

	// 4. Run terraform init & terraform apply
	terraform.InitAndApply(t, opts)

	// 5. Fetch output from state
	albDnsName := terraform.Output(t, opts, "alb_dns_name")
	url := fmt.Sprintf("http://%s", albDnsName)

	// 6. Assert live HTTP response with retries (waiting for EC2 user_data boot)
	expectedStatus := 200
	expectedBody := "Hello, World"
	maxRetries := 30
	timeBetweenRetries := 5 * time.Second

	http_helper.HttpGetWithRetryWithCustomValidation(
		t,
		url,
		&tls.Config{},
		maxRetries,
		timeBetweenRetries,
		func(status int, body string) bool {
			return status == expectedStatus && strings.Contains(body, expectedBody)
		},
	)
}
```

## Anti-patterns

- **Running Terratest Against Production Cloud Accounts**:
  - *Why it fails*: Risks deleting or mutating live production databases during `defer terraform.Destroy`. Always use dedicated sandbox accounts.
- **Forgetting `defer terraform.Destroy(t, opts)`**:
  - *Why it fails*: Test failures halt execution early, leaving orphaned EC2/ALB assets running indefinitely, burning thousands of dollars.
- **Hardcoding Test Resource Names**:
  - *Why it fails*: Parallel CI test runs clash on global namespace assets (like S3 buckets or IAM roles). Use `random.UniqueId()`.
- **Relying Solely on End-to-End Tests**:
  - *Why it fails*: E2E tests are slow and expensive. Catch syntax/policy bugs instantly at Layer 1 (`tflint`/`checkov`) and Layer 2 (`terraform test`).

---

## Key Takeaways

1. **Shift Left with Static Analysis**: Run `terraform fmt`, `validate`, `tflint`, and `checkov` in pre-commit hooks and PR builds.
2. **Use Native `terraform test`**: Write HCL unit tests (`.tftest.hcl`) with mock providers for fast, zero-cost logic validation.
3. **Always Use `defer Destroy` in Terratest**: Ensure infrastructure cleanup runs even when tests fail.
4. **Configure Automatic Retries**: Set `MaxRetries` in Terratest to handle transient cloud provider API rate limits.
