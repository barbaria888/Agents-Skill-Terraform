# Chapter 3 — How to Manage Terraform State

## What is State?

Terraform stores information about your managed infrastructure and configuration in a state file (`terraform.tfstate`).
- Maps resources in code to real-world infrastructure.
- Tracks metadata (dependencies, resource IDs).
- Optimizes performance (caching resource attributes).

## 1. Remote Backend Setup (S3 + DynamoDB)

By default, state is stored locally. For teams, you must use a **remote backend** with shared storage and locking.

### Step A: Create the Storage & Locking Resources

First, apply this configuration using a local state (since S3/DynamoDB don't exist yet):

```hcl
provider "aws" {
  region = "us-east-2"
}

# 1. S3 bucket to store state
resource "aws_s3_bucket" "terraform_state" {
  bucket        = "my-company-terraform-state-bucket"
  force_destroy = false # Prevent accidental deletion of state
}

# Enable versioning so we can roll back state files if corrupt
resource "aws_s3_bucket_versioning" "enabled" {
  bucket = aws_s3_bucket.terraform_state.id
  versioning_configuration {
    status = "Enabled"
  }
}

# Enable server-side encryption by default
resource "aws_s3_bucket_server_side_encryption_configuration" "default" {
  bucket = aws_s3_bucket.terraform_state.id

  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm = "AES256"
    }
  }
}

# Explicitly block all public access to the S3 bucket
resource "aws_s3_bucket_public_access_block" "public_access" {
  bucket                  = aws_s3_bucket.terraform_state.id
  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}

# 2. DynamoDB table for locking state
resource "aws_dynamodb_table" "terraform_locks" {
  name         = "my-company-terraform-locks"
  billing_mode = "PAY_PER_REQUEST"
  hash_key     = "LockID" # MUST be exactly LockID

  attribute {
    name = "LockID"
    type = "S"
  }
}
```

### Step B: Configure the Backend

Once the resources are deployed, add the `backend` block to your configurations:

```hcl
terraform {
  backend "s3" {
    bucket         = "my-company-terraform-state-bucket"
    key            = "global/s3/terraform.tfstate"
    region         = "us-east-2"
    dynamodb_table = "my-company-terraform-locks"
    encrypt        = true
  }
}
```

Run `terraform init` to migrate your local state to S3.

## 2. State Isolation Strategies

Never put all resources in a single state file. A bug or crash could destroy your entire infrastructure (blast radius).

### Strategy A: Workspaces (Avoid for Production)
Terraform Workspaces allow you to store state for multiple environments in the *same* S3 key path (prefixed by workspace name).

- **Pros**: Quick to set up.
- **Cons**: All environments share the same backend authentication/variables. High risk of accidentally running `apply` in the wrong workspace.

```bash
terraform workspace new stage
terraform workspace select stage
terraform workspace list
```

### Strategy B: File Layout (Recommended)
Isolate environments by placing configurations in completely separate subdirectories:

```
stage/
  vpc/
    main.tf
    outputs.tf
    variables.tf
  services/
    web-cluster/
      main.tf
      ...
  data-stores/
    mysql/
      main.tf
      ...
prod/
  vpc/
  ...
```

- Each directory has its own backend configuration (different S3 key).
- Blast radius is minimized.
- Easier access control (IAM permissions can restrict access to `/prod` S3 prefix).

## 3. Remote State Read-Only Access (`terraform_remote_state`)

When you isolate configurations into separate directories, they cannot directly reference each other's resources. Use `terraform_remote_state` to read outputs from another state file:

### Example: Web Cluster needs DB Address

#### 1. In `data-stores/mysql/outputs.tf`:
```hcl
output "address" {
  value       = aws_db_instance.example.address
  description = "Connect to the database at this endpoint"
}

output "port" {
  value       = aws_db_instance.example.port
  description = "The port the database is listening on"
}
```

#### 2. In `services/web-cluster/main.tf`:
```hcl
data "terraform_remote_state" "db" {
  backend = "s3"

  config = {
    bucket = "my-company-terraform-state-bucket"
    key    = "stage/data-stores/mysql/terraform.tfstate"
    region = "us-east-2"
  }
}

# Reference remote output
user_data = templatefile("user_data.sh", {
  db_address = data.terraform_remote_state.db.outputs.address
  db_port    = data.terraform_remote_state.db.outputs.port
})
```
