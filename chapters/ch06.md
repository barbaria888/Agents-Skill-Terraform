# Chapter 6 — Managing Secrets with Terraform

## Core Idea
Secrets (database passwords, API keys, TLS certificates, SSH keys) must **never** be stored in plain text in HCL code or checked into version control. Managing secrets in Terraform requires combining secret management backends (AWS Secrets Manager, HashiCorp Vault), environment variable overrides, input validation guardrails (`precondition`/`postcondition`), and strict state file encryption and access controls.

---

## Frameworks Introduced

### 1. The 2 Golden Rules of Secrets Management
1. **Rule #1**: Do NOT store secrets in plain text.
2. **Rule #2**: **DO NOT STORE SECRETS IN PLAIN TEXT.**
   - *Why*: Storing secrets in plain-text code grants access to anyone with Git access, clones copies onto dozens of developer laptops, exposes credentials to any software running on those machines, and leaves zero audit trails.

### 2. The 3 Techniques for Passing Secrets into Terraform

| Technique | How it Works | Advantages | Drawbacks |
|---|---|---|---|
| **Environment Variables** | Inject via `TF_VAR_<name>` environment variables at shell runtime | Keeps secrets out of code; easy integration with CI runners | Manual machine setup; secrets visible in shell history if logged |
| **Encrypted Files (sops / KMS)** | Encrypt `.json`/`.yaml` files with KMS/PGP; decrypt dynamically in memory | Secrets stored in Git in encrypted form; trackable changes | Requires external decryption tools/scripts; key management overhead |
| **Centralized Secret Stores (Vault / AWS SM)** | Store secrets in Vault or AWS Secrets Manager; fetch at runtime via `data` blocks | Central audit log, secret rotation, RBAC access policies, zero secrets in Git | Operational overhead of secret store; requires cloud authentication |

### 3. The State File & Plan File Leakage Warning
> [!WARNING]  
> **Terraform State Files (`.tfstate`) and Saved Plan Files (`tfplan`) store ALL resource attributes in plain-text JSON — including variables marked `sensitive = true`!**  
> Marking a variable `sensitive = true` only hides it from `stdout` terminal output; it does NOT encrypt it in state files or plan artifacts.

## Code Examples

### 1. Technique 1: Environment Variables (`TF_VAR_`)
```hcl
# variables.tf
variable "db_password" {
  description = "Master password for PostgreSQL database"
  type        = string
  sensitive   = true # Suppresses terminal CLI output
}

# main.tf
resource "aws_db_instance" "example" {
  identifier_prefix   = "app-db-"
  engine              = "postgres"
  allocated_storage   = 20
  instance_class      = "db.t3.micro"
  username            = "dbadmin"
  password            = var.db_password # Injected via TF_VAR_db_password
  skip_final_snapshot = true
}
```

```bash
# In shell / CI runner:
export TF_VAR_db_password="SuperSecurePassword123!"
terraform apply
```

### 2. Technique 2: Centralized Secret Store (AWS Secrets Manager)
```hcl
# 1. Query existing secret metadata from AWS Secrets Manager
data "aws_secretsmanager_secret" "db_credentials" {
  name = "prod/db/credentials"
}

# 2. Fetch the latest secret version payload
data "aws_secretsmanager_secret_version" "db_credentials" {
  secret_id = data.aws_secretsmanager_secret.db_credentials.id
}

# 3. Parse JSON secret payload inside local values
locals {
  db_creds = jsondecode(
    data.aws_secretsmanager_secret_version.db_credentials.secret_string
  )
}

# 4. Inject credentials into Database Resource
resource "aws_db_instance" "example" {
  identifier_prefix   = "app-db-"
  engine              = "postgres"
  allocated_storage   = 20
  instance_class      = "db.t3.micro"
  username            = local.db_creds.username
  password            = local.db_creds.password
  skip_final_snapshot = true
}
```

### 3. Technique 3: HashiCorp Vault Provider
```hcl
provider "vault" {
  address = "https://vault.example.com:8200"
}

data "vault_generic_secret" "db_credentials" {
  path = "secret/db"
}

resource "aws_db_instance" "example" {
  identifier_prefix   = "app-db-"
  engine              = "postgres"
  allocated_storage   = 20
  instance_class      = "db.t3.micro"
  username            = data.vault_generic_secret.db_credentials.data["username"]
  password            = data.vault_generic_secret.db_credentials.data["password"]
  skip_final_snapshot = true
}
```

### 4. Custom Precondition & Postcondition Guardrails
```hcl
# Validate inputs BEFORE creating resource
resource "aws_db_instance" "example" {
  identifier_prefix   = "app-db-"
  engine              = "postgres"
  allocated_storage   = 20
  instance_class      = "db.t3.micro"
  username            = local.db_creds.username
  password            = local.db_creds.password
  skip_final_snapshot = true

  lifecycle {
    # Precondition check
    precondition {
      condition     = length(local.db_creds.password) >= 16
      error_message = "Database master password must be at least 16 characters long."
    }

    # Postcondition check on resource creation
    postcondition {
      condition     = self.encrypted == true
      error_message = "PRODUCTION ERROR: Database instance must have storage encryption enabled."
    }
  }
}
```

## State & Plan File Security Checklist

- [ ] **Remote Backend Encryption**: Always set `encrypt = true` in S3 backend block.
- [ ] **Restricted S3 Bucket IAM**: Grant S3 bucket `GetObject`/`PutObject` write access ONLY to CI/CD automated runners, never developer accounts.
- [ ] **Plan File Encryption**: Encrypt `tfplan` artifacts if saved in CI/CD pipeline steps (`gpg --encrypt tfplan`).
- [ ] **Mark Sensitive Variables**: Always tag variables and outputs with `sensitive = true`.
- [ ] **Enable KMS CMK**: Use Customer Managed Keys (CMK) with key rotation for AWS Secrets Manager and S3 backends.

---

## Anti-patterns

- **Hardcoding Passwords in `.tf` Files or `terraform.tfvars`**:
  - *Why it fails*: `.tfvars` files are easily committed to Git by mistake, exposing plain-text secrets across developer machines and commit history.
- **Assuming `sensitive = true` Encrypts State Files**:
  - *Why it fails*: `sensitive = true` only redacts terminal CLI text output. Raw JSON state files (`terraform.tfstate`) still contain the plain-text string.
- **Committing Unencrypted `tfplan` Artifacts**:
  - *Why it fails*: Saved plan files generated by `terraform plan -out=tfplan` contain all resolved variable values in plain text.

---

## Key Takeaways

1. **Never Store Secrets in Plain Text**: Use environment variables or centralized secret stores (AWS SM / Vault).
2. **Treat State Files as Sensitive Vaults**: Protect state files with S3 encryption, DynamoDB locking, and restrictive IAM policies.
3. **Use `precondition` for Guardrails**: Enforce password length, complexity, and encryption flags directly in HCL code.
4. **Use OIDC for Cloud Authentication**: Avoid storing static AWS access keys in CI/CD environments; authenticate CI/CD runners using OpenID Connect (OIDC).
