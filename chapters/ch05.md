# Chapter 5 — Loops, Conditionals, Deployments, and Gotchas

## Core Idea
Declarative languages require specialized constructs to handle iteration, dynamic block generation, and conditional logic. Terraform provides `count`, `for_each`, `for` expressions, and `dynamic` blocks. Additionally, zero-downtime deployments require orchestrating resource replacement lifecycles (`create_before_destroy`) alongside dynamic naming.

---

## Frameworks Introduced

### 1. The 4 Loop Constructs Framework

| Construct | Operates On | Best Used For | Key Trait / Limitations |
|---|---|---|---|
| **`count`** | Integer / List | Simple enable/disable boolean toggles (`count = var.enable ? 1 : 0`) | ⚠️ **Index-sensitive**: Deleting items from middle of list forces recreation of subsequent resources. |
| **`for_each`** | Set / Map | Creating multiple distinct resources based on keys | ✅ **Key-stable**: Safe against element additions/deletions. Maps to unique keys in state (`aws_iam_user.example["alice"]`). |
| **`for` Expression** | List / Map | Transforming complex structures inside locals or arguments | Operates inline inside expressions (`[for s in var.names : upper(s)]`). |
| **`dynamic` Block** | Map / Set | Generating repeated *nested blocks* inside a resource (e.g. repeated `ingress` blocks) | Operates inside resource blocks; uses `content {}` sub-block. |

### 2. The Conditional Creation Framework
- **Resource Conditional**: `count = var.enable_feature ? 1 : 0`
- **Conditional Output**: `value = try(aws_autoscaling_group.example[0].arn, null)` or `one(aws_autoscaling_group.example[*].arn)`
- **Ternary Operator**: `condition ? true_val : false_val`

### 3. Zero-Downtime ASG Deployment Pattern Framework
To deploy code changes to an Auto Scaling Group without downtime:
1. Wrap ASG Launch Template / Launch Config in `lifecycle { create_before_destroy = true }`.
2. Append the launch configuration / template hash/name to the ASG `name_prefix` or `name` attribute.
3. Set `lifecycle { create_before_destroy = true }` on the ASG resource itself.
4. When launch config changes, Terraform creates the *new* ASG first, registers instances with target group, verifies health, and then destroys the *old* ASG.

## Code Examples

### 1. `for_each` Loop over Map (`iam.tf`)
```hcl
variable "custom_user_tags" {
  description = "Map of username to job title"
  type        = map(string)
  default = {
    neo   = "hero"
    trinity = "developer"
    morpheus = "captain"
  }
}

resource "aws_iam_user" "example" {
  for_each = var.custom_user_tags
  name     = each.key

  tags = {
    Title = each.value
  }
}

output "user_arns" {
  value = values(aws_iam_user.example)[*].arn
}
```

### 2. `for` Expressions and String Directives (`expressions.tf`)
```hcl
variable "names" {
  type    = list(string)
  default = ["neo", "trinity", "morpheus"]
}

# Transform List to Uppercase List
locals {
  upper_names = [for name in var.names : upper(name)]
  
  # Filter List
  short_names = [for name in var.names : name if length(name) < 5]

  # Map Transformation
  name_lengths = { for name in var.names : name => length(name) }
}

# String Directive (HCL Heredoc Loop)
output "for_string_directive" {
  value = "%{ for name in var.names }${name}, %{ endfor }"
}
```

### 3. `dynamic` Block Generation (`security_group.tf`)
```hcl
variable "ingress_rules" {
  description = "List of ingress rules"
  type = list(object({
    port        = number
    description = string
  }))
  default = [
    { port = 80, description = "HTTP" },
    { port = 443, description = "HTTPS" },
    { port = 8080, description = "App Port" }
  ]
}

resource "aws_security_group" "example" {
  name = "dynamic-ingress-sg"

  dynamic "ingress" {
    for_each = var.ingress_rules
    content {
      description = ingress.value.description
      from_port   = ingress.value.port
      to_port     = ingress.value.port
      protocol    = "tcp"
      cidr_blocks = ["0.0.0.0/0"]
    }
  }
}
```

### 4. Zero-Downtime ASG Replacement Pattern (`asg.tf`)
```hcl
resource "aws_launch_template" "example" {
  name_prefix   = "web-lt-"
  image_id      = var.ami_id
  instance_type = "t3.micro"

  user_data = base64encode(templatefile("${path.module}/user_data.sh.tpl", {
    server_port = var.server_port
  }))

  # 1. Ensure new template is created before old one is destroyed
  lifecycle {
    create_before_destroy = true
  }
}

resource "aws_autoscaling_group" "example" {
  # 2. Dynamic name forces ASG replacement when launch template changes
  name                 = "${var.cluster_name}-${aws_launch_template.example.name_latest_version}"
  launch_template {
    id      = aws_launch_template.example.id
    version = "$Latest"
  }

  vpc_zone_identifier = var.subnet_ids
  target_group_arns   = [var.target_group_arn]
  health_check_type   = "ELB"

  min_size = 2
  max_size = 10

  # 3. Create new ASG & wait for healthy instances before destroying old ASG
  lifecycle {
    create_before_destroy = true
  }

  # 4. Instance refresh strategy for rolling updates without replacing ASG
  instance_refresh {
    strategy = "Rolling"
    preferences {
      min_healthy_percentage = 50
    }
  }
}
```

## Key Gotchas

### Gotcha 1: `count` and `for_each` Cannot Depend on Computed Resource Attributes
- You CANNOT pass a computed value (e.g. `aws_vpc.example.id` created in the *same* run) to `for_each` or `count` if it determines keys/length.
- *Reason*: Terraform must calculate `count`/`for_each` keys during the `plan` phase, *before* resources are created.

### Gotcha 2: `count` List Shift Destruction
- If you use `count = length(var.users)` on a list `["alice", "bob", "charlie"]` and remove `"alice"`, index `0` becomes `"bob"` and index `1` becomes `"charlie"`.
- Terraform will delete/recreate `bob` and `charlie` because their index address changed! **Fix**: Always use `for_each` with sets or maps for resources.

### Gotcha 3: Plans Can Lie
- `terraform plan` checks syntax and queries read APIs, but CANNOT detect runtime errors (e.g. invalid IAM permissions, unavailable AMI region specs, subnet space exhaustion).
- Only `terraform apply` executes real writes.

---

## Anti-patterns

- **Using `count` for Heterogeneous Resource Collections**:
  - *Why it fails*: Deleting any item from the middle of the list triggers cascading resource destructions. Use `for_each`.
- **Overusing `dynamic` Blocks**:
  - *Why it fails*: Makes HCL look like complex procedural code, degrading readability. Use `dynamic` blocks only when repeating inner blocks (like `ingress` or `subnet`).

---

## Key Takeaways

1. **Prefer `for_each` over `count`**: Use `for_each` for resource iteration to ensure stable key identifiers in state.
2. **Use `count` Only for Boolean Flags**: Use `count = var.enable ? 1 : 0` to optionally toggle a resource.
3. **Master `create_before_destroy`**: Always use dynamic naming + `create_before_destroy` for zero-downtime ASG deployments.
4. **Use `one()` for Conditional Outputs**: `one(aws_resource.example[*].id)` converts 0-element or 1-element lists cleanly to scalar outputs.
