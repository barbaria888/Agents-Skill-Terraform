# Chapter 5 — Loops, Conditionals, Deployments, and Gotchas

## 1. Loops

Terraform provides several loop constructs depending on whether you are repeating resources, nested blocks, or transforming values.

### Loop A: `count` (Lists)
Used to create multiple copies of a resource using a list.

```hcl
resource "aws_iam_user" "example" {
  count = length(var.user_names)
  name  = var.user_names[count.index]
}
```
*Gotcha: If you delete an item from the middle of `var.user_names`, Terraform shifts all index positions after it, causing it to rename or recreate resources. Use `for_each` instead.*

### Loop B: `for_each` (Maps/Sets)
Creates multiple copies of a resource from a map or set of strings. Safe from re-indexing issues.

```hcl
resource "aws_iam_user" "example" {
  for_each = toset(var.user_names)
  name     = each.value # or each.key
}
```

### Loop C: `for` expression (Value Transformation)
Transforms lists, maps, or sets.

```hcl
# Output a list of uppercase names
output "upper_names" {
  value = [for name in var.user_names : upper(name) if length(name) > 3]
}
```

### Loop D: `dynamic` block (Nested Loops)
Repeats nested blocks *within* a resource (e.g., repeating `ingress` blocks inside a security group).

```hcl
resource "aws_security_group" "example" {
  name = "dynamic-ports"

  dynamic "ingress" {
    for_each = var.custom_ingress_rules
    content {
      from_port   = ingress.value.port
      to_port     = ingress.value.port
      protocol    = "tcp"
      cidr_blocks = ingress.value.cidr_blocks
    }
  }
}
```

## 2. Conditionals (If-Statements)

### If-Statement: `count`
Control resource creation based on a boolean.

```hcl
variable "enable_autoscaling" {
  type    = bool
  default = true
}

resource "aws_autoscaling_schedule" "scale_out" {
  count                  = var.enable_autoscaling ? 1 : 0
  scheduled_action_name  = "scale-out-business-hours"
  min_size               = 2
  max_size               = 10
  desired_capacity       = 5
  recurrence             = "0 9 * * *"
  autoscaling_group_name = aws_autoscaling_group.example.name
}
```

### Conditional Outputs
Provide optional values based on whether a resource was created.

```hcl
output "asg_arn" {
  value       = one(aws_autoscaling_group.example[*].arn)
  description = "The ARN of the Auto Scaling Group if enabled"
}
```

## 3. Zero-Downtime Deployments (ASG Rollover)

When updating a Launch Configuration inside an ASG, Terraform's default behavior is to delete the ASG and recreate it, causing downtime. Use the `create_before_destroy` lifecycle parameter:

```hcl
resource "aws_launch_configuration" "example" {
  image_id        = "ami-0fb653ca2d3203ac1"
  instance_type   = "t2.micro"
  security_groups = [aws_security_group.instance.id]

  lifecycle {
    create_before_destroy = true
  }
}

resource "aws_autoscaling_group" "example" {
  # Depend directly on name to force ASG replacement on Launch Config updates
  name                 = "${var.cluster_name}-${aws_launch_configuration.example.name}"
  launch_configuration = aws_launch_configuration.example.name
  vpc_zone_identifier  = data.aws_subnets.default.ids
  
  min_size = 2
  max_size = 10

  lifecycle {
    create_before_destroy = true
  }
}
```

- When the `aws_launch_configuration` is updated, it gets a new name.
- The ASG references this name. Since ASG `name` includes the launch config name, it forces ASG replacement.
- With `create_before_destroy = true` on the ASG:
  1. Terraform creates a second, new ASG first.
  2. The new ASG registers its new instances with the ALB.
  3. ALB routes traffic to both.
  4. Once instances are healthy, Terraform destroys the old ASG.

## 4. Key Gotchas

### Gotcha 1: `count` and `for_each` limitations
You cannot use computed values (values resolved during `apply`, such as IDs of resources created in the same run) in `count` or `for_each`. They must be known at `plan` time.

### Gotcha 2: Launch Configurations are Immutable
You cannot modify an existing AWS launch configuration. To update one, Terraform must create a new one. Ensure `create_before_destroy = true` is defined on it and any referencing ASGs.

### Gotcha 3: Plans Can Lie
`terraform plan` only runs static analysis and read-only API calls. Some failures (e.g. invalid AMI permissions, subnet exhaustion, or IAM authorization issues) only surface during `terraform apply`.
