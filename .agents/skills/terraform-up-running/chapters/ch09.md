# Chapter 9 — Testing Terraform Code

Testing infrastructure presents unique challenges because test execution requires interacting with actual cloud provider APIs, creating real resources that cost money.

## 1. Static Analysis (Fast, Cheap)

Run static checks on every pull request to catch syntax, style, and security issues without deploying anything.

- **`terraform fmt -check`**: Checks if files are formatted according to canonical guidelines.
- **`terraform validate`**: Validates syntax, attribute names, and basic structural validity.
- **`tflint`**: Linter that checks for cloud-specific errors (e.g. invalid EC2 instance types).
- **`checkov` / `tfsec`**: Scans configuration for security vulnerabilities and compliance issues (e.g., S3 buckets open to the public).

## 2. Unit Testing in HCL (`terraform test`)

Since Terraform 1.6+, you can write native unit tests in HCL using `.tftest.hcl` files.

### Example: Testing a Module (`tests/website.tftest.hcl`)
```hcl
# Set up variables for this test run
variables {
  server_port = 8080
}

# Run block executes terraform apply
run "validate_alb_dns_name" {
  command = apply

  # Assert output properties match expectations
  assert {
    condition     = startswith(output.alb_dns_name, "terraform-asg-example")
    error_message = "ALB DNS name did not start with expected prefix"
  }
}
```

Run tests:
```bash
terraform test
```

## 3. Integration Testing with Go (`Terratest`)

For comprehensive, end-to-end testing, write test files in Go using **Terratest**. Terratest deploys actual infrastructure, runs assertions against live resources, and cleans them up.

### Example Go Test File (`test/web_cluster_test.go`)
```go
package test

import (
	"crypto/tls"
	"fmt"
	"testing"
	"time"

	"github.com/gruntwork-io/terratest/modules/http-helper"
	"github.com/gruntwork-io/terratest/modules/terraform"
)

func TestWebCluster(t *testing.T) {
	t.Parallel()

	opts := &terraform.Options{
		// Path to the root terraform folder to test
		TerraformDir: "../examples/web-cluster",

		// Variables to pass to the apply command
		Vars: map[string]interface{}{
			"cluster_name": "test-cluster",
		},
	}

	// Clean up resources at the end of the test run
	defer terraform.Destroy(t, opts)

	// Run terraform init & apply
	terraform.InitAndApply(t, opts)

	// Grab public output
	albDnsName := terraform.Output(t, opts, "alb_dns_name")
	url := fmt.Sprintf("http://%s", albDnsName)

	// Assert endpoint returns a 200 OK with "Hello, World"
	expectedBody := "Hello, World"
	maxRetries := 30
	timeBetweenRetries := 5 * time.Second

	http_helper.HttpGetWithRetryWithCustomValidation(
		t,
		url,
		&tls.Config{},
		maxRetries,
		timeBetweenRetries,
		func(status int, body string) bool {
			return status == 200 && body == expectedBody
		},
	)
}
```

To run the Go test suite:
```bash
cd test
go test -v -timeout 30m
```

## 4. Best Practices for Testing

1. **Test in Isolation**: Create separate AWS/GCP developer sub-accounts for testing to ensure tests do not touch production resources.
2. **Always Run Defer Destroy**: Always use `defer` (in Go) or ensure cleanup steps run in your CI to prevent orphaned resources from costing money.
3. **Use Random Identifiers**: Use random names for resources in tests to prevent naming collisions when running multiple tests concurrently.
   ```hcl
   resource "random_uuid" "id" {}

   resource "aws_s3_bucket" "test" {
     bucket = "test-bucket-${random_uuid.id.result}"
   }
   ```
