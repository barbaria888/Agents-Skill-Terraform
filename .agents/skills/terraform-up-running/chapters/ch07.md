# Chapter 7 — Working with Multiple Providers, Regions, and Accounts

In real-world setups, you often need to manage resources across multiple cloud providers, regions, or accounts within the same configuration.

## 1. Multiple Regions (Provider Aliases)

Use **aliases** to define multiple configurations for the same provider (e.g., to create a multi-region deployment).

```hcl
# Default provider configuration (Primary Region)
provider "aws" {
  region = "us-east-2"
}

# Alternate provider configuration (Secondary Region)
provider "aws" {
  alias  = "west"
  region = "us-west-2"
}

# Resource in the primary region
resource "aws_instance" "primary" {
  ami           = "ami-0fb653ca2d3203ac1" # us-east-2 AMI
  instance_type = "t2.micro"
}

# Resource in the secondary region
resource "aws_instance" "secondary" {
  provider      = aws.west # Reference provider by alias
  ami           = "ami-04505e74c0741db8d" # us-west-2 AMI
  instance_type = "t2.micro"
}
```

## 2. Multiple Accounts (IAM Roles)

To deploy across different cloud accounts (e.g. staging vs production), use different AWS credentials or assume different IAM roles in provider blocks.

```hcl
provider "aws" {
  alias  = "parent"
  region = "us-east-2"
}

provider "aws" {
  alias  = "child"
  region = "us-east-2"

  assume_role {
    role_arn     = "arn:aws:iam::123456789012:role/TerraformDeploymentRole"
    session_name = "terraform-session"
  }
}
```

## 3. Passing Providers to Modules

Modules inherit default provider configurations automatically. However, if a module needs to use an aliased provider, you must pass it explicitly.

### In the Child Module (`modules/multi-region-s3/main.tf`):
```hcl
terraform {
  required_providers {
    aws = {
      source                = "hashicorp/aws"
      configuration_aliases = [aws.primary, aws.replica] # Require these inputs
    }
  }
}

resource "aws_s3_bucket" "primary" {
  provider = aws.primary
  bucket   = var.primary_bucket_name
}

resource "aws_s3_bucket" "replica" {
  provider = aws.replica
  bucket   = var.replica_bucket_name
}
```

### In the Calling Root Module:
```hcl
provider "aws" {
  alias  = "east"
  region = "us-east-2"
}

provider "aws" {
  alias  = "west"
  region = "us-west-2"
}

module "s3_buckets" {
  source = "./modules/multi-region-s3"

  # Pass providers explicitly to match child configuration aliases
  providers = {
    aws.primary = aws.east
    aws.replica = aws.west
  }

  primary_bucket_name = "my-company-primary-bucket"
  replica_bucket_name = "my-company-replica-bucket"
}
```

## 4. Multi-Cloud Deployments

Terraform can orchestrate multiple entirely distinct providers within a single run (e.g. creating an AWS RDS Database and a Kubernetes service that connects to it).

```hcl
provider "aws" {
  region = "us-east-2"
}

provider "kubernetes" {
  config_path = "~/.kube/config"
}

resource "aws_db_instance" "postgres" {
  allocated_storage   = 20
  engine              = "postgres"
  instance_class      = "db.t3.micro"
  db_name             = "appdb"
  username            = "dbuser"
  password            = var.db_password
  skip_final_snapshot = true
}

resource "kubernetes_secret" "db_credentials" {
  metadata {
    name = "db-credentials"
  }

  data = {
    address  = aws_db_instance.postgres.address
    port     = aws_db_instance.postgres.port
    username = aws_db_instance.postgres.username
    password = var.db_password
  }
}
```
