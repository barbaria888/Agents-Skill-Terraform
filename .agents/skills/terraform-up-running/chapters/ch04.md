# Chapter 4 — How to Create Reusable Infrastructure with Terraform Modules

## What is a Module?

Any set of Terraform configuration files in a folder is a **module**. 
- The folder where you run `terraform apply` is the **root module**.
- A module that is loaded by another is a **child module**.

## 1. Module Structure

A standard module directory layout looks like this:

```
modules/
  services/
    web-cluster/
      main.tf        # Resources (ALB, ASG, Security Groups)
      variables.tf   # Module input variables
      outputs.tf     # Module output variables
```

### Example Module Definition (`modules/services/web-cluster/variables.tf`)
```hcl
variable "cluster_name" {
  description = "Name prefix for cluster resources"
  type        = string
}

variable "db_remote_state_bucket" {
  description = "Name of S3 bucket for RDS remote state"
  type        = string
}

variable "db_remote_state_key" {
  description = "Key path of RDS remote state file"
  type        = string
}
```

### Referencing the Module (`stage/services/web-cluster/main.tf`)
```hcl
module "web_cluster" {
  source = "../../../../modules/services/web-cluster"

  cluster_name           = "web-cluster-stage"
  db_remote_state_bucket = "my-company-terraform-state"
  db_remote_state_key    = "stage/data-stores/mysql/terraform.tfstate"
}
```

## 2. Module Inputs, Outputs, and Locals

### Inputs (Variables)
Pass values from the calling module into the child module.

### Outputs
Expose properties of resources in the child module to the calling module.

```hcl
# In modules/services/web-cluster/outputs.tf:
output "asg_name" {
  value       = aws_autoscaling_group.example.name
  description = "The name of the Auto Scaling Group"
}

# In stage/services/web-cluster/main.tf:
resource "aws_autoscaling_schedule" "scale_out" {
  scheduled_action_name  = "scale-out-during-business-hours"
  min_size               = 2
  max_size               = 10
  desired_capacity       = 5
  recurrence             = "0 9 * * *" # 9 AM daily
  autoscaling_group_name = module.web_cluster.asg_name
}
```

### Locals
Define local variables within a module to store intermediate expressions and avoid hardcoded duplication. Local variables are scoped strictly to the module they are defined in.

```hcl
locals {
  http_port    = 80
  any_port     = 0
  any_protocol = "-1"
  tcp_protocol = "tcp"
  all_ips      = ["0.0.0.0/0"]
}
```

## 3. Module Gotchas

### Inline Blocks vs Standalone Resources
Some resources allow configuration via *inline blocks* OR *standalone resources*.
- **Security Groups**: `ingress` block inside `aws_security_group` VS `aws_security_group_rule` resource.
- **Route Tables**: `route` block inside `aws_route_table` VS `aws_route` resource.

**Golden Rule**: Never mix both. Standardize on **standalone resources** for modules so calling configurations can dynamically add rules/routes.

```hcl
# Standardize on standalone rule resources
resource "aws_security_group" "default" {
  name = var.sg_name
}

resource "aws_security_group_rule" "allow_http" {
  type              = "ingress"
  security_group_id = aws_security_group.default.id
  from_port         = 80
  to_port           = 80
  protocol          = "tcp"
  cidr_blocks       = ["0.0.0.0/0"]
}
```

### Module Paths
When using file paths inside a child module (e.g., `user_data = file("user-data.sh")`), Terraform resolves paths relative to the **root module** where `apply` is run, NOT the child module.

**Fix**: Use `path.module` to resolve paths relative to the child module:
```hcl
user_data = file("${path.module}/user-data.sh")
```
- `path.module`: Returns the filesystem path to the child module.
- `path.root`: Returns the filesystem path to the root module.
- `path.cwd`: Returns the current working directory.
