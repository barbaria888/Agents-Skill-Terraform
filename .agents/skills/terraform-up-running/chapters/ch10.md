# Chapter 10 — How to Use Terraform as a Team

Successful infrastructure operations in a team require defining a strict lifecycle for code review, validation, deployment, and access permissions.

## 1. The Pull Request Workflow

All changes to infrastructure must follow a peer-reviewed version-controlled workflow:

1. **Feature Branch**: Developer pulls a new branch from `main`.
2. **Local Validation**: Developer runs `terraform fmt` and `terraform validate`.
3. **Open Pull Request**: Developer pushes branch and opens a PR.
4. **CI Automated Plan**: The CI system automatically runs `terraform plan` and comments the diff back on the PR.
5. **Peer Review**: At least one other engineer reviews the code and the plan output.
6. **Merge to main**: Once approved, the branch is merged into `main`.
7. **CD Automated Apply**: The CD system detects the merge and applies the changes to live environments.

## 2. PR Automation: Atlantis

**Atlantis** is an open-source self-hosted pull-request automation server for Terraform.

- **How it Works**: Instead of running plans locally, developers trigger Atlantis via Git PR comments.
- **Workflow**:
  - Developer leaves comment: `atlantis plan`
  - Atlantis runs the plan on its worker node, posts the output comment back onto the PR, and locks the state.
  - Peer reviews and approves the PR.
  - Developer leaves comment: `atlantis apply`
  - Atlantis applies the plan, unlocks the state, and merges the PR.
- **Benefits**:
  - Lock state at the PR level (prevents other PRs from running overlapping plans).
  - No need to distribute AWS/GCP administrative credentials to developers' local machines.

## 3. Managed Services: Terraform Cloud (TFC)

Terraform Cloud is HashiCorp's managed SaaS platform that provides:

- **Remote Runs**: Executes plans/applies in a clean containerized environment.
- **VCS Integration**: Triggers runs automatically on GitHub commits or PRs.
- **Private Module Registry**: Hosts private company modules.
- **Policy as Code (Sentinel / OPA)**: Enforces business logic before apply (e.g. "Do not allow public S3 buckets" or "Only allow t3.* instances").
- **State Hosting**: Managed secure storage with automatic locks and encryption.

## 4. CDKTF vs. Pulumi

For developers who prefer writing standard programming languages over HCL configuration:

### Cloud Development Kit for Terraform (CDKTF)
Enables compiling standard languages (TypeScript, Python, Java, Go) into HCL, which is then deployed using the standard Terraform CLI.

```typescript
import { App, TerraformStack } from "cdktf";
import { AwsProvider } from "@cdktf/provider-aws/lib/provider";
import { Instance } from "@cdktf/provider-aws/lib/instance";

class MyStack extends TerraformStack {
  constructor(scope: App, id: string) {
    super(scope, id);
    new AwsProvider(this, "AWS", { region: "us-east-1" });
    new Instance(this, "server", {
      ami: "ami-0fb653ca2d3203ac1",
      instanceType: "t2.micro",
    });
  }
}
```

### Pulumi
A distinct Provisioning engine that runs native code execution directly against cloud APIs (using standard languages), bypassing Terraform's HCL format entirely but sharing similar state-tracking mental models.
